# Notes — Atelier 3 : Spring Data JPA et Repositories

## 1. Choix de l'interface JpaRepository

Nous avons choisi `JpaRepository<Entité, Long>` pour les 9 entités.
- **Pourquoi ?** `JpaRepository` hérite de `CrudRepository` et `PagingAndSortingRepository`. Elle offre donc le CRUD complet, les méthodes de tri/pagination, et des méthodes spécifiques à JPA comme `flush()` et `saveAndFlush()`.
- **Différence Iterable / List** : `CrudRepository.findAll()` renvoie un `Iterable` (moins pratique). `JpaRepository` renvoie un `List` (plus pratique pour boucler ou faire un `.size()`).
- **Attention aux suppressions en lot** : Les méthodes `deleteAllInBatch()` et `deleteAllByIdInBatch()` de `JpaRepository` exécutent une requête SQL directe et **contournent le contexte de persistance**. Par conséquent, le `cascade = REMOVE` et l'`orphanRemoval` **ne s'appliquent pas**. Supprimer des contrats ainsi laisserait des paiements orphelins en base, ce qui violerait l'intégrité référentielle (erreur de clé étrangère).
